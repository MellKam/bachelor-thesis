Bachelor's thesis · WebAssembly exposure study

How far does each language reach into WebAssembly, and what does it cost to use?

1 · The evidence

Counts only, no weights. Every language–feature pair was probed and lands in exactly one of five buckets.

2 · The summary

One number per language; the right panel shows how much the ranking moves when every coefficient is perturbed.

3 · Reading the score

Each bar is the best possible result: every feature reached fully, with nothing in the way. What a language keeps is its score; the rest is split by cause.

4 · Trade-offs

Reaching far, reaching cleanly and being checked are three different things

Support is how much of the feature set a language can produce. Directness is how few obstacles stand in the way of what it reaches. Checked is how much of what it reaches the compiler type-checks.

5 · Over time

The same score, computed separately for the features each WebAssembly spec release introduced.

7 · What gets in the way

Among the features a language does reach, how many carry each kind of obstacle. Rows run from the mildest penalty to the harshest.

8 · Using the module

What it takes to use the module a language produces, scored separately from exposure. Each column is one test that was built and run.

9 · Toolchain cost

Not scored and not part of the combined result: how heavy the official toolchain is, and how long a first build takes.

10 · Putting it together

The exposure score (sections 1–7) and the integration score (section 8) side by side, then combined into one number. The 0.6 / 0.4 split is a choice: change it and the order may change, which is what the range of ranks shows.
